# Verify finalization and indexes

A failed mutation must not be accepted into an updated baseline, and index reuse must not silently change the lines or identifiers selected for mutation testing.

From the repository root, run `./.agents/skills/verify-finalization-indexes/check.sh`. It requires Go, Java, Python 3 and Bash. It downloads a checksum-pinned TLC jar on first use. TLC explores every combination of five boolean finalization inputs. The real-code checks cover a missing ID, successful baseline update, update with errors, report failure, individual-ID gate bypass and gate failure. They also check that generate mode retains a write failure after a later success, compare an incremental identifier query with a fresh one after clearing, rebuild the safety cache, and check repeated coverage and per-test hits and misses. Scratch Go overlays remove the update error guard, forget the write failure, skip identifier collection, and disable the path cache. Each must fail its matching behavior test for the named reason; the check then runs the unmodified test again. The cache test inserts a key after a miss only to observe the miss latch. Production profiles are populated before lookup.

The checked production functions are `planFinalization` and `finalizeResults` in `internal/engine/engine.go`, `generateSink.admit` and `finish` in `internal/engine/mode.go`, `identifierIndex.query` and `ensure` in `astutil/query.go`, `indexRegistry` in `astutil/index_registry.go`, `getSafetyIndex` in `astutil/safety.go`, and `pathResolver.resolve`, `Profile.IsCovered` and `PerTestProfile.CoveringTests` in `internal/coverage/coverage.go`. Inspect changes to these operations, including the working tree, before running. Compare the transitions to `Finalize.tla` and the real-code tests; update the checks for intentional behavior changes. The source baseline is `6d28414`. Advance the sync commit only after checking the code and passing the checks and `/statechart` review.

Read every model result with `/statechart`. Replay a counterexample against the named functions before treating it as a product bug. The TLA+ model checks the abstract decision order and assumes a baseline write succeeds. The concrete test includes report failure but does not exhaust all output formats, concurrent executions or filesystem failures. The index checks cover one nested query sequence and a safety-cache rebuild, not all AST shapes or interleavings; the path probe covers repeated hit and miss and longest-suffix selection, not mutable published profiles. The model does not cover indexes. A failed build, timeout or unrelated assertion is not a successful sensitivity check.
