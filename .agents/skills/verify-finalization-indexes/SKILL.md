# Verify finalization and indexes

A failed mutation must not be accepted into an updated baseline, and index reuse must not silently change the lines or identifiers selected for mutation testing.

From the repository root, run `./.agents/skills/verify-finalization-indexes/check.sh`. It requires Go, Java, Python 3 and Bash. It downloads a checksum-pinned TLC jar on first use. TLC explores every combination of five boolean finalization inputs. The real-code checks cover a missing ID, successful baseline update, update with errors, report failure, individual-ID gate bypass and gate failure. They also check that generate mode retains a write failure after a later success, compare an incremental identifier query with a fresh one after clearing, rebuild the safety cache, and check repeated coverage and per-test hits and misses. Scratch Go overlays remove the update error guard, forget the write failure, skip identifier collection, skip safety clearing, and disable the path cache. Each must fail its matching behavior test for the named reason; the check then runs the unmodified test again. The path cache test inserts a key after a miss only to observe the miss latch. The safety test changes synthetic type information to expose a stale index after a clear. Production profiles are populated before lookup.

The checked production functions are `planFinalization` and `finalizeResults` in `internal/engine/engine.go`, `generateSink.admit` and `finish` in `internal/engine/mode.go`, `identifierIndex.Query` and `ensure` in `astutil/query.go`, `indexRegistry` in `astutil/index_registry.go`, `getSafetyIndex` in `astutil/safety.go`, and `pathResolver.resolve`, `Profile.IsCovered` and `PerTestProfile.CoveringTests` in `internal/coverage/coverage.go`. Inspect changes to these operations, including the working tree, before running. Compare the transitions to `Finalize.tla` and the real-code tests; update the checks for intentional behavior changes. The source baseline is `7bc356292989fda5ecb9c608c25f518576e48ca7`. Advance the sync commit only after checking the code and passing the checks and `/statechart` review.

Read every result from both `Finalize.tla` and `Indexes.tla` with `/statechart`. Replay a counterexample against the named functions before treating it as a product bug. The finalization model checks abstract decision order and assumes a baseline write succeeds. The index model explores every subset of two abstract nodes and both a path hit and a miss, including lazy safety construction, safety-only clear, complete index clear and repeated lookups. It checks that every covered range has been collected, a built safety index belongs to the current generation, and cached paths match their immutable source. Its epoch is a model device for tracking a reset, not a production field. The checker deliberately breaks each modeled property and requires the named invariant to fail before restoring the model. The production probes provide the link to the real code.

The concrete finalization test includes report failure but does not exhaust all output formats, concurrent executions or filesystem failures. The index probes cover one nested query sequence and a safety-cache rebuild, not all AST shapes or interleavings; the path probe covers repeated hit and miss and longest-suffix selection, not mutable published profiles. Model operations are atomic abstractions of the locked owners and assume source data is immutable while indexed. The model does not establish race freedom, prove memory bounds, or model source positions and AST mutation. A failed build, timeout or unrelated assertion is not a successful sensitivity check.
